# Service Request Workflow Architecture

---

## 1. Ticket Number Standard
Every service request automatically receives a structured reference tracking number:
```
FACSS-SR-YYYY-XXXXXX
```
Example: `FACSS-SR-2026-359204`

---

## 2. The 9-Stage Status Lifecycle

```
[ NEW ]
   │
   ▼
[ UNDER_REVIEW ] ──────► [ CONTACTED ]
   │                           │
   ▼                           ▼
[ APPROVED ]  ◄────── [ WAITING_FOR_CLIENT ]
   │
   ▼
[ IN_PROGRESS ]
   │
   ▼
[ REPORT_READY ]
   │
   ▼
[ COMPLETED ]   (or [ CANCELLED ])
```

1. `NEW`: Newly generated by client or public quote wizard.
2. `UNDER_REVIEW`: Triage by Security Operations Lead.
3. `CONTACTED`: Client reached by dispatch officer.
4. `WAITING_FOR_CLIENT`: Awaiting building blueprints or site access clearances.
5. `APPROVED`: Security plan and commercial contract ratified.
6. `IN_PROGRESS`: Cadres and technical gear deployed on-site.
7. `REPORT_READY`: Vulnerability assessment or inspection document ready.
8. `COMPLETED`: Final deliverable handed over to client.
9. `CANCELLED`: Closed upon mutual agreement.

---

## 3. Transparency & Privacy Controls
- **Internal Notes:** Strictly hidden from the client portal; recorded for command audit.
- **Client-Visible Notes:** Rendered in the client portal timeline with timestamp.
- **Attachments:** Secure, non-public document access.
