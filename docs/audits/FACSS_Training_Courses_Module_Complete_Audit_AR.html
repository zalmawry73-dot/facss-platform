الملخص التنفيذي (Executive Summary)

أجرت هذه المراجعة المستقلة تدقيقاً شاملاً ومقيداً للقراءة فقط (Read-Only Audit) لوحدة إدارة التدريب والدورات (Training & Courses Module) داخل منصة المركز المتكامل لخدمات الأمن والسلامة والدراسات الميدانية (FACSS). شمل الفحص بنية الكود المصدري، ومسارات API، ونماذج قاعدة البيانات في Prisma، وقواعد التحقق الإجرائي (Validation Layers)، وتدفقات العمل التشغيلية، ومحددات الأمن والصلاحيات (RBAC).

✅ أهم نقاط القوة والتميز التشغيلي المكتشفة في الوحدة:
  • بنية تحتية متقدمة لإصدار الشهادات والتحقق العام: يعتمد النظام رقم شهادة فريد متسلسل سنويًا (FACSS-CERT-2026-NNNN) مقترناً برمز تحقق تشفيري 96-بت (24 حرف هيكس)، مع بوابة تحقق عامة مفتوحة للجمهور (/verify/[code]) تحافظ على خصوصية المتدرب وتحجب أسباب الإلغاء الإداري.
  • محرك تقارير مبني على البيانات الفعلية الحية 100%: تم التحقق من مسار /api/admin/training/[id]/report ومكون TrainingReportModal.tsx، حيث يتم حساب مؤشرات الإنجاز، ونسبة الحضور التراكمية، ومعدل التحسن في التقييم القبلي/البعدي (Improvement Gain %)، ومؤشرات الرضا استناداً إلى سجلات قاعدة البيانات الحقيقية ودون أي قيم عشوائية وهمية (Zero Mock Data).

  • حماية الدورات المسجلة من الحذف التدميري: في حال محاولة حذف دورة تحتوي على تسجيلات لمتدربين، يمنع مسار DELETE /api/admin/training/[id] الحذف المادي ويحوّل حالة الدورة تلقائياً إلى CANCELLED حفاظاً على السجلات والشهادات الصادرة.

1. حدود التدقيق الملتزم بها (Read-Only Mandate)

  • لم يتم تعديل أي ملف برمجي، واجهة، مسار، أو دالة داخل المشروع.
  • لم يتم إنشاء أو حذف أو تعديل أي سجل في قاعدة البيانات، ولم يتم تنفيذ أي ترحيل (Migration).
  • لم يتم تثبيت أو تعديل أي حزمة في package.json.
  • لم يتم إنشاء أي طلب سحب (Pull Request) أو ارتكاب حفظ (Git Commit).

2. المنهجية المتبعة في التدقيق

اعتمدت المنهجية على الهندسة العكسية الصارمة للكود الفعلي (Static Code Analysis & Flow Tracing):

  1. فحص طبقة البيانات: تدقيق مخطط prisma/schema.prisma، والعلاقات، ومحددات الحذف (Cascade)، والقيود الفريدة (Unique Constraints)، والفهارس.
  2. فحص منطق الأعمال (Backend Logic): تتبع 19 مسار API و Server Actions للتحقق من المصادقة، والتحقق من المدخلات عبر lib/validations/admin.ts، وفرض الصلاحيات عبر lib/rbac.ts.
  3. فحص واجهات المستخدم (Frontend Logic): مراجعة مكونات لوحة الإدارة components/admin/TrainingManager.tsx ومكونات الأكاديمية وبوابة المتدرب وبوابة العميل وبوابة التحقق العامة.
  4. فحص التكاملات وسجلات التدقيق: تتبع استدعاءات logActivity ونظام الإشعارات Notification والتكامل مع بقية الوحدات المؤسسية.
⚠️ إفصاح فني إلزامي بخصوص الاتصال بقاعدة البيانات الحية:

أثناء تنفيذ التدقيق، تبيّن أن خادم قاعدة بيانات PostgreSQL المحلي على العنوان 127.0.0.1:5433 (المعرف في ملف .env) غير نشط (Connection Refused). وامتثالاً للشرط الإلزامي الصريح في وثيقة التدقيق ("إذا تعذر الوصول إلى قاعدة البيانات، اذكر ذلك ولا تدّعِ أنك تحققت من بياناتها")، نؤكد أن نتائج التدقيق وحالات الجداول استُخرجت من فحص ملف التهيئة الأولي scripts/seed.js، واختبارات E2E في scripts/qa_phase7/، ومخطط Prisma والـ Migrations، والمسارات البرمجية، ولم يتم الاستعلام المباشر من قاعدة بيانات مشغلة.

الحضور والغياب وتدقيق شرط الـ 75% (Attendance Audit)

1. مستوى تسجيل الحضور في النظام

يتم تسجيل الحضور على مستوى الجلسة التدريبية (Session Level) من خلال ربط سجل AttendanceRecord بمعرّف الجلسة sessionId والتسجيل registrationId. حالات الحضور المعتمدة في الـ Enum هي: PRESENT, ABSENT, EXCUSED.

2. تدقيق شرط نسبة الحضور (75%) في الكود الفعلي

وفق متطلبات المركز المعتمدة، يجب ألا تقل نسبة حضور المتدرب عن 75% كشرط إلزامي للتخرج ونيل الشهادة. أثبت التدقيق أن حقل minAttendancePct Float @default(75) موجود في نموذج Course. ويتم التحقق منه في مسار إصدار الشهادة app/api/admin/training/certificates/route.ts:152-167:

// كود التحقق الفعلي من الحضور في certificates/route.ts const totalSessions = registration.course.sessions.length; if (totalSessions > 0) { const presentCount = registration.attendanceRecords.filter((a) => a.status === 'PRESENT').length; const attendancePct = Math.round((presentCount / totalSessions) * 100); const minRequired = registration.course.minAttendancePct ?? 75; if (attendancePct < minRequired) { return NextResponse.json( { error: `المتدرب غير مؤهل للحصول على الشهادة: نسبة الحضور الفعلية (${attendancePct}%) أقل من الحد الأدنى المطلوب (${minRequired}%).` }, { status: 400 } ); } }
⚠️ ثغرة خطيرة في تطبيق شرط الحضور (P1):

لاحظ الشرط if (totalSessions > 0): إذا أنشأت الإدارة دورة دون إدخال جلسات تفصيلية في جدول TrainingSession، فإن totalSessions يكون 0، وبالتالي يتم تخطي كود فحص الحضور بالكامل! هذا يتيح إصدار شهادة تخرج معتمدة لمتدرب لم يحضر يوماً واحداً.

3. نافذة تصحيح الحضور وتدقيق التعديلات (Correction Audit Trail)

يوفر مسار PUT /api/admin/training/[id]/attendance ميزة ممتازة تتيح تصحيح حالة الحضور السابقة، مع إلزام المسؤول بإدخال حقول التتبع: modifiedReason (سبب التعديل) و modifiedById و modifiedAt، وتسجيل النشاط في ActivityLog.

الاختبارات والتقييم الأكاديمي والنتائج (Evaluations & Academic Grading)

1. التنفيذ الفعلي للتقييم القبلي والبعدي (PRE & POST Evaluations)

تتضمن قاعدة البيانات نموذج TrainingEvaluation مقيداً بالقيد الفريد @@unique([registrationId, type]) حيث يكون type إما PRE (تقييم قبلي) أو POST (تقييم بعدي). ويتحكم الحقلان requiresPreEval و requiresPostEval في نموذج Course بإلزامية كل تقييم.

2. إدارة الأسئلة مقابل رصد الدرجات (Crucial Finding)

📌 حقيقة وظيفية هامة: النظام لا يدير امتحانات إلكترونية

أثبت التدقيق بالدليل القاطع أن منصة FACSS لا تحتوي على محرك اختبارات أونلاين (Online Exam Engine) ولا بنك أسئلة، وبوابة المتدرب لا توفر واجهة لتقديم اختبارات. ما هو منفذ فعلياً هو رصد درجات إداري (Score Recording)، حيث يقوم المدرب أو المسؤول بإدخال الدرجة المستحقة (score) والدرجة القصوى (maxScore @default(100)) والملاحظات التي حققها المتدرب في الاختبار الورقي أو العملي الميداني.

3. معادلة حساب نسبة التحسن الأكاديمي (Improvement Gain %)

في مسار التقرير الأكاديمي app/api/admin/training/[id]/report/route.ts:93-107، يطبق النظام معادلة إحصائية حقيقية لحساب نسبة التحسن في المعارف الميدانية:

const prePct = (preEval.score / preEval.maxScore) * 100; const postPct = (postEval.score / postEval.maxScore) * 100; const denom = Math.max(1, 100 - prePct); const gain = ((postPct - prePct) / denom) * 100; totalGainPct += gain;

تقيس هذه المعادلة نسبة الفجوة المعرفية التي تم ردمها بين الاختبار القبلي والبعدي بدقة عالية.

الشهادات والتحقق الرقمي (Certificates & Verification System)

1. شروط استحقاق الشهادة الإلزامية في الخادم

وفق مسار POST /api/admin/training/certificates/route.ts، لا يمكن إصدار الشهادة إلا بعد استيفاء الشروط التالية مجتمعة:

  1. أن تكون حالة تسجيل المتدرب COMPLETED حصراً (خطوة 2).
  2. أن تكون الدورة داعمة لإصدار الشهادات (course.hasCertificate = true).
  3. عدم وجود شهادة سابقة نشطة لنفس التسجيل (منع التكرار خطوة 4).
  4. استيفاء نسبة الحضور 75% (مع وجود ثغرة التخطي إذا كانت الجلسات = 0).
  5. اجتياز وإكمال التقييم البعدي (POST) إذا كانت الدورة تشترطه (خطوة 6).

2. الهوية التشفيرية للشهادة ومنع التزوير

  • رقم الشهادة: يتم توليده بتسلسل محكم FACSS-CERT-{YYYY}-{NNNN} عبر دالة generateCertificateNumber.
  • رمز التحقق التشفيري: يتم توليده عبر مكتبة التشفير crypto.randomBytes(12).toString('hex').toUpperCase() مما يمنح رمزاً بطول 24 حرفاً ذو عشوائية 96-بت (مستحيل التخمين أو التزوير).
  • محرك إلغاء الشهادات (Revocation): يدعم النظام إلغاء الشهادات الصادرة مع تسجيل السبب وتاريخ الإلغاء وحفظ السجل.

3. الخصوصية في بوابة التحقق العامة

في app/verify/[code]/page.tsx، عند تحقق أي جهة خارجية من صحة الشهادة، يعرض النظام اسم المتدرب، عنوان الدورة، تاريخ الإصدار، والتقدير العام، مع حجب البريد الإلكتروني، ورقم الهاتف، والرقم الوطني، وسبب الإلغاء الإداري لحماية خصوصية بيانات المتدربين الميدانيين.

⚠️ نقص فني: غياب التوليد المباشر لملفات PDF

حقل pdfPath في جدول Certificate يظل null دائماً عند الإصدار، حيث لا يوجد محرك توليد PDF في الخادم (مثل Puppeteer أو PDFKit). يعتمد النظام على عرض قالب HTML أنيق في بوابة المتدرب وتفعيل خيار window.print() للحفظ كـ PDF من المتصفح.

التقارير ومؤشرات الأداء الأكاديمية (Academic KPIs & Reporting)

1. المؤشرات المتوفرة فعلياً في التقرير الختامي الحقيقي

بالرجوع إلى مسار app/api/admin/training/[id]/report/route.ts، يتم استخراج المؤشرات التالية لحظياً من قاعدة البيانات:

  • إجمالي المسجلين (Total Enrolled): course.registrations.length.
  • نسبة الإكمال العام (Completion Rate): نسبة المتدربين بحالة COMPLETED إلى إجمالي المسجلين.
  • نسبة الحضور الفعلي التراكمية (Overall Attendance %): مجموع جلسات الحضور (PRESENT) مقسوماً على إجمالي سجلات الحضور.
  • معدل التحسن الأكاديمي (Academic Improvement Gain %): يقيس الفارق بين التقييم القبلي والبعدي استناداً لمعادلة الفجوة المعرفية.
  • عدد الشهادات الصادرة والملغاة: إحصاء دقيق للشهادات السارية والشهادات التي تم إلغاؤها (isRevoked: true).
  • مؤشر رضا المتدربين (Overall Satisfaction): متوسط التقييمات من 5 نجوم لمحتوى الدورة، أداء المدرب، والتنظيم الميداني.

2. المؤشرات الناقصة التي يحتاجها المركز

  • التكلفة والعائد المالي للدورة: لا توجد حقول مالية لتسجيل رسوم الدورة، مكافآت المدربين، أو تكاليف استهلاك المواد في قاعة المحاكاة.
  • مؤشر الالتزام بالحضور حسب القطاع: تصنيف نسب الحضور والغياب للمنظمات الإنسانية مقارنة بالشركات التجارية.

السيناريو 2: نشر دورة غير مكتملة البيانات أو بدون تواريخ قصور إجرائي
المستخدم / الدور: مسؤول التدريب.

المستخدم / الدور: حساب متدرب (TRAINEE).
ما يحدث فعلياً في الكود: يستدعي POST /api/training/register. يتحقق الخادم من وجود الدورة، وحالتها OPEN، ونوعها PUBLIC، وتوفر مقاعد، وعدم وجود تسجيل مسبق، ثم ينشئ الطلب بحالة PENDING ويرسل إشعاراً للمتدرب.

السيناريو 4: امتلاء مقاعد الدورة والطلبات المتزامنة ثغرة حرجة P1
