1. إصلاح الفجوة GAP-01: تمكين تعيين ضباط العمليات والكادر الميداني

ملفات الإصلاح: app/api/admin/staff/route.ts | app/admin/requests/page.tsx | components/admin/RequestsManager.tsx

✓ مكتمل ومفحوص

التشخيص الهندسي: كان حقل قاعدة البيانات assignedEmployeeId مدعوماً في Prisma ومسار PATCH /api/requests/[id]، ولكن في واجهة المستخدم RequestsManager.tsx لم يكن هناك أي مدخل لاختيار الموظف، كما لم تكن واجهة الخادم تستعلم عن الموظفين المؤهلين للتعيين.

أ) بناء نقطة النهاية المخصصة للكادر التشغيلي الميداني:
// app/api/admin/staff/route.ts export async function GET() { const session = await getCurrentUser(true); if (!session || !isStaffRole(session.role)) { return NextResponse.json({ error: 'Unauthorized: Staff access required' }, { status: 401 }); } const staff = await prisma.user.findMany({ where: { isActive: true, role: { in: STAFF_ROLES }, // [SUPER_ADMIN, ADMIN, STAFF, SERVICE_MANAGER, ...] }, select: { id: true, fullName: true, email: true, phone: true, role: true }, orderBy: { fullName: 'asc' }, }); return NextResponse.json({ success: true, staff }); }
ب) دمج قائمة الاختيار في نافذة إدارة الطلب الميداني:
// components/admin/RequestsManager.tsx <AdminSelect label="تعيين ضابط / موظف العمليات الميدانية المسؤول" value={assignedEmployeeId} onChange={(e) => setAssignedEmployeeId(e.target.value)} options={[ { value: '', label: '-- بدون تعيين (قيد الانتظار) --' }, ...operationalStaff.map((s) => ({ value: s.id, label: `${s.fullName} (${s.role})`, })), ]} />

2. إصلاح الفجوة GAP-02: الإدارة البرمجية الكاملة لمجالات النشاط المؤسسي

ملفات الإصلاح: app/api/admin/services/categories/route.ts | components/admin/ServicesCatalogManager.tsx

✓ مكتمل ومفحوص

التشخيص الهندسي: كانت لوحة تحكم الخدمات تمكن المسؤول من تعديل بيانات الخدمة الفردية فقط، بينما كانت مجالات النشاط المؤسسي (Service Categories) ثابتة وغير قابلة للإضافة أو التعديل برمجياً، مما تسبب في عزل أقسام الشركة الجديدة عن النظام.

أ) دعم التوليد الآلي للمعرف (Slug) ومزامنة كتل المحتوى المؤسسي:
// app/api/admin/services/categories/route.ts // Sync with ContentBlock (section: 'activity_fields') for seamless public CMS display if ((prisma as any).contentBlock) { await (prisma as any).contentBlock.upsert({ where: { section_key: { section: 'activity_fields', key: finalSlug }, }, update: { titleAr: titleAr.trim(), titleEn: titleEn.trim(), order: Number(order) || 0, isVisible: Boolean(isActive), }, create: { section: 'activity_fields', key: finalSlug, titleAr: titleAr.trim(), titleEn: titleEn.trim(), order: Number(order) || 0, isVisible: Boolean(isActive), }, }); }
ب) واجهات المودال المتطورة في ServicesCatalogManager:
  • إضافة زر علوي بارز + إضافة مجال نشاط مؤسسي جديد.
  • إضافة زر إعدادات وتعديل بجانب اسم كل مجال نشاط لتعديل مسمى المجال، الـ Slug، الأيقونة، الترتيب، وحالة التفعيل اللحظي.
  • تحديث بيانات الواجهة بدون الحاجة لإعادة تحميل الصفحة (Optimistic UI Update).

3. إصلاح الفجوة GAP-03: الجسر الآلي لتحويل طلبات التدريب إلى دورات بالأكاديمية

ملفات الإصلاح: app/api/admin/requests/[id]/convert-to-course/route.ts | components/admin/RequestsManager.tsx

✓ مكتمل ومفحوص

التشخيص الهندسي: عند تقديم طلب خدمة ينتمي لمجال "التدريب الأمني والتأهيل الميداني"، كان الطلب ينتهي كملف نصي جامد في جدول الطلبات، وكان على مدير التدريب إعادة إدخال بيانات الدورة يدوياً في الأكاديمية دون أي ربط مرجعي بين طلب العميل والدورة المنشأة.

أ) محرك تحويل الطلب إلى دورة تدريبية مخصصة (Private Client Course Engine):
// app/api/admin/requests/[id]/convert-to-course/route.ts const newCourse = await prisma.course.create({ data: { categoryId: courseCategory.id, titleAr: `[دورة مخصصة] ${srvTitle} — ${orgName}`, titleEn: `[Private Training] ${srvTitleEn} — ${orgName}`, slug: uniqueGeneratedSlug, descriptionAr: `دورة تدريبية متخصصة منبثقة عن طلب الخدمة الميدانية رقم [${reqRecord.requestNumber}] لصالح: ${orgName}.\n\nنطاق الاحتياج:\n${reqRecord.description}`, courseType: 'PRIVATE_CLIENT', // ربط خاص بالمنشأة الشريكة deliveryMode: 'IN_PERSON', clientId: reqRecord.userId || null, targetAudienceAr: orgName, capacity: 25, status: 'DRAFT', }, }); // تسجيل ملاحظة إجرائية رسمية للعميل والإدارة await prisma.serviceRequestNote.create({ data: { requestId, authorName: session.fullName, note: `🎓 تم تحويل هذا الطلب واعتماد دورة تدريبية خاصة بالأكاديمية بنجاح بعنوان: "${newCourse.titleAr}".`, isClientVisible: true, }, });

ثالثاً: السيناريوهات التشغيلية الشاملة من البداية حتى النهاية (End-to-End Walkthroughs)

فيما يلي تفصيل دقيق لأربعة سيناريوهات تشغيلية واقعية تغطي دورة الحياة الكاملة لكافة الأطراف الفاعلة في المنصة:

سيناريو 1

دورة حياة العميل / المنشأة الشريكة (End-to-End Enterprise Client)

استكشاف مجالات النشاط المؤسسي، طلب خدمة ميدانية، ومتابعة التقارير والملاحظات المعتمدة.

الجهة الفاعلة: ممثل شركة نفطية / منظمة دولية (دور CLIENT)
1
1.1 استكشاف دليل الخدمات ومجالات النشاط المؤسسي
GET /services
يقوم ممثل المنشأة بزيارة بوابة الخدمات للتعرف على مجالات نشاط المركز: (الحراسات الأمنية والمنشآت الحيوية، إدارة المخاطر واستشارات السلامة، التقييم الأمني والمسح الميداني، التدريب الأمني والتأهيل الميداني).
البيانات المعروضة قائمة بطاقات مجالات النشاط، عدد الخدمات المتاحة تحت كل مجال، والوصف المختصر.
المخرجات البرمجية استعلام خادم سريع يجلب ServiceCategory النشطة مرتبة حسب حقل order.
2
1.2 الاطلاع على المواصفات الفنية ونطاق العمل
GET /services/[slug]
اختيار خدمة محددة (مثل: "التقييم الأمني الشامل للمنشآت الحيوية") لمعاينة تفاصيل المنهجية الميدانية، الميزات الاستراتيجية، القطاعات المستهدفة، ومسار التنفيذ المرحلي من المعاينة حتى التقرير النهائي.
3
1.3 تقديم طلب خدمة ميدانية رسمية
POST /api/requests
النقر على زر "تقديم طلب لهذه الخدمة"، حيث يقوم النموذج بتعبئة اسم المنشأة وبيانات الاتصال تلقائياً من الملف التعريفي للعميل (ClientProfile)، ويقوم العميل بإدخال نطاق الاحتياج ومستوى الأولوية (عادي / عاجل / طارئ).
الاستجابة الفورية توليد كود تتبع فريد بنمط FACSS-SR-2026-000105، وتعيين الحالة الابتدائية NEW.
الإشعارات إرسال إشعار لحظي لحساب العميل وتنبيه إدارة العمليات عبر سجل النظام.
4
1.4 متابعة مسار العمل والاطلاع على الملاحظات والوثائق
GET /dashboard/requests
يدخل العميل إلى لوحة المتابعة الخاصة به للاطلاع على:
  • تحديثات الحالة التشغيلية من قبل إدارة المركز (قيد المراجعة ➔ تم التكليف ➔ العمليات الميدانية جارية ➔ جاهزية التقرير).
  • الملاحظات الفنية المفتوحة للعميل (المعينة بـ isClientVisible = true).
  • التقارير الأمنية ومحاضر التسليم المرفوعة والمعتمدة من قبل إدارة الجودة.
سيناريو 2

دورة حياة ضابط العمليات الميدانية المكلف (Field Operations Lifecycle)

استلام التكليف، تحديث المسار التشغيلي، تسجيل الملاحظات الفنية، ورفع التقارير المعتمدة.

الجهة الفاعلة: ضابط العمليات الميدانية / خبير الاستشارات (دور SERVICE_MANAGER / EMPLOYEE)
1
2.1 استلام إشعار التكليف وظهور الطلب في سجل المهام
GET /admin/requests
بعد قيام مدير العمليات بتعيين ضابط العمليات عبر القائمة المنسدلة المستحدثة (الإصلاح GAP-01)، يظهر الطلب لضابط العمليات مع تمييز شارة التكليف باسمه وبيانات المنشأة المستفيدة.
2
2.2 تحديث مسار الحالة التشغيلية
PATCH /api/requests/[id]
يقوم ضابط العمليات بفتح نافذة إدارة الطلب وتغيير الحالة من NEW إلى CONTACTED (تم التواصل مع ممثل المنشأة لتحديد موعد الزيارة الميدانية) ثم إلى IN_PROGRESS (بدء المسح الميداني).
3
2.3 تسجيل الملاحظات الميدانية (عامة للعميل أو داخلية محجوبة)
POST /api/requests/[id]/notes
إضافة قيود الإنجاز اليومي:
  • ملاحظة ظاهرة للعميل: "تم الانتهاء من المعاينة الميدانية للمحيط الأمني للمنشأة، وفريق العمل يعكف حالياً على إعداد تقرير تقييم الثغرات".
  • ملاحظة داخلية محجوبة: "تم رصد نقطة عمياء في كاميرات المراقبة بالبوابة الخلفية تتطلب توصية خاصة في التقرير السري".
4
2.4 رفع الوثائق الفنية والتقارير الأمنية وإغلاق الطلب
POST /api/admin/requests/[id]/documents
رفع ملف التقرير الفني النهائي (PDF)، وتحديد نوع الوثيقة FINAL_REPORT، وتمريره لمسار مراجعة الجودة، وعند اعتماده يتم نقل حالة الطلب تلقائياً إلى COMPLETED.
سيناريو 3

دورة حياة تحويل طلب تدريب ميداني إلى دورة خاصة بالأكاديمية (Academy Course Bridge)

التكامل التلقائي بين طلبات الخدمات وبوابة تدريب الكوادر الأمنية.

الجهة الفاعلة: مدير التدريب والأكاديمية (دور TRAINING_MANAGER / ADMIN)
1
3.1 تدقيق طلب التدريب الأمني الوارد من المنشأة
GET /admin/requests?filter=training
ورود طلب من منشأة مصرفية بعنوان: "برنامج تدريب حراس أمن المنشآت المصرفية والتعامل مع الطوارئ" يضم 25 متدرباً.
2
3.2 تفعيل التحويل الآلي للأكاديمية بنقرة واحدة
POST /api/admin/requests/[id]/convert-to-course
في نافذة إدارة الطلب بتبويب "التفاصيل الأساسية"، تظهر بطاقة الأكاديمية الجديدة: النقر على زر "تحويل الطلب إلى دورة خاصة بالأكاديمية".
ما يحدث خلف الكواليس إنشاء سجل في جدول Course بنوع PRIVATE_CLIENT، وربط clientId بحساب العميل.
التقدم الإجرائي للطلب ترقية حالة طلب الخدمة تلقائياً إلى APPROVED، وتوليد ملاحظة نظامية موثقة للمستفيد.
3
3.3 استكمال الجدولة والمواد التدريبية في لوحة الأكاديمية
GET /admin/training
يفتح الرابط المباشر في صفحة الأكاديمية حيث يجد مدير التدريب الدورة مجهزة بالكامل بعنوان: "[دورة مخصصة] تدريب حراس أمن المنشآت المصرفية — بنك الأمل". يقوم مدير التدريب بتعيين المدربين المعتمدين، مواعيد القاعات، ورفع الحقيبة التدريبية.
سيناريو 4

دورة حياة مدير النظام ومسؤول المحتوى (Super Admin & CMS Management)

استحداث مجال نشاط جديد، مزامنة البوابة العامة، وتدقيق سجلات الأنشطة.

الجهة الفاعلة: مدير النظام العام / مدير المحتوى (دور SUPER_ADMIN / CONTENT_MANAGER)
1
4.1 استحداث وتعديل مجالات النشاط المؤسسي
POST /api/admin/services/categories
الدخول إلى دليل الخدمات /admin/services والنقر على الزر الجديد: "إضافة مجال نشاط مؤسسي". إدخال: (العنوان بالعربية، العنوان بالإنجليزية، أيقونة Lucide، والترتيب).
المزامنة التلقائية مع CMS يقوم النظام بحفظ الفئة ومزامنة سجل في جدول ContentBlock بقسم activity_fields ليظهر فوراً في الواجهة العامة والصفحة الرئيسية.
تدقيق الأمان وسجل النشاط تسجيل حركة CREATE_SERVICE_CATEGORY في جدول ActivityLog مع توثيق هوية المسؤول وعنوان الـ IP.
2
4.2 إضافة وتخصيص الخدمات الميدانية التابعة للمجال
POST /api/admin/services
إضافة باقات الخدمات الميدانية تحت المجال الجديد مع تحديد الميزات، القطاعات المستهدفة، ومسار العمل المرحلي ومراجعة ظهورها باللغتين العربية والإنجليزية.

خلاصة الاعتماد التشغيلي للمنصة

تؤكد هذه الوثيقة أن جميع وحدات الخدمات والأنشطة الميدانية في منصة FACSS تعمل الآن بتناغم مؤسسي متكامل يلبي أعلى معايير الجودة والأمان الرقمي. تم ربط تجربة العميل مباشرة بفرق العمليات الميدانية ومحرك الأكاديمية مع توفير إدارة مركزية مرنة وشفافة لكافة مجالات النشاط المعتمدة لمركز الحلول المتكاملة للأمن والسلامة.
